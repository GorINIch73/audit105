# audit105

Аудит оборота по счёту 105: импорт ODS/XLSX/XML, разбор позиций, применение правил, отчёты и сравнение прогонов.

## Главное меню

Справочники вынесены в отдельное меню:

- **Правила → Правила** — редактирование правил.
- **Правила → Категории** — редактирование категорий.
- **Правила → Термины и списки** — редактирование терминов, в том числе больших списков недопустимых лекарств.
- **Правила → Сводка и очередь** — сводка по прогону и позиции, которые не распознаны ни одним правилом.

Каждая форма справочника содержит:

- фильтры и поиск;
- таблицу записей слева;
- панель редактирования справа;
- кнопки **Добавить**, **Сохранить**, **Удалить**, **Пред.**, **След.**, **Сбросить**;
- пагинацию для больших списков.

## Категории

Категория — это группа правил и цветовая метка в отчётах.

Поля:

- `name` — название категории;
- `color` — цвет в формате `#RRGGBB`;
- `description` — пояснение;
- `sort_order` — порядок отображения;
- `active` — активна ли категория.

Правила ссылаются на категорию по имени. Если категория удалена, правило остаётся, но теряет смысловую группу.

## Правила

Правило описывает, как отметить позицию.

Поля:

- `code` — уникальный код правила, например `S01`;
- `category` — название категории;
- `type` — тип правила;
- `pattern` — шаблон проверки;
- `severity` — серьёзность от 0 до 3;
- `rationale` — основание/пояснение;
- `source_doc` — источник правила;
- `active` — применять ли правило.

Порядок применения правил:

```text
structural → exact → synonym → term → regex
```

Позиция может получить несколько отметок от разных правил.

## Общий синтаксис шаблона

Для большинства типов правила шаблон может содержать ограничение по субсчётам:

```text
sub:105.31,105.32; <тело шаблона>
```

Если `sub:` отсутствует, правило применяется ко всем субсчётам.

## Типы правил

### structural

Проверяет арифметику и структуру позиции.

Возможные шаблоны:

```text
arith
qty_missing
qty_mismatch
negative
no_turnover:10000
zero_qty
```

Пример:

```text
sub:105.31,105.32; no_turnover:10000
```

Значения:

- `arith` — не сходится арифметика: начало + оборот не равно конец;
- `qty_missing` — нет строки количества;
- `qty_mismatch` — сумма и количество заполнены неравномерно;
- `negative` — отрицательный остаток на конец периода;
- `no_turnover:threshold` — нет оборота, но остаток больше порога;
- `zero_qty` — сумма есть, количество нулевое.

### exact

Ищет точные дубликаты.

Возможные шаблоны:

```text
signature
name
```

Пример:

```text
sub:105.31; name
```

Значения:

- `signature` — совпадают наименование, субсчёт и все суммы;
- `name` — совпадают наименование и субсчёт.

### synonym

Ищет позиции по списку синонимов.

Шаблон — список слов через запятую:

```text
шприц, игла, инъекция
```

Пример с субсчётами:

```text
sub:105.31; шприц, игла
```

Синонимы сравниваются с нормализованным наименованием позиции.

### term

Правило типа `term` использует справочник терминов.

Связь:

```text
rule.code = term.rule_code
```

Если для правила есть активные термины, они используются как список совпадений. Если терминов нет, используется тело шаблона правила как запасной список.

Пример:

```text
Правило: T01, type = term, pattern = sub:105.31;
Термины: иммуноглобулин, вакцины, перевязочные материалы
```

### regex

Ищет наименование позиции по регулярному выражению.

Шаблон — ECMAScript-подобное регулярное выражение:

```text
^вакцина|иммуноглобулин
```

Пример с субсчётами:

```text
sub:105.31; ^вакцина
```

## Термины и списки

Термин — это запись справочника, которая привязывается к правилу типа `term`.

Поля:

- `rule_code` — код правила;
- `term` — исходный термин;
- `term_norm` — нормализованный термин;
- `scope` — область применения, например `local` или `global`;
- `origin` — источник: `manual` или `import`;
- `list_name` — название перечня;
- `source_doc` — документ-источник;
- `as_of_date` — дата актуальности;
- `active` — активен ли термин.

Нормализация:

- регистр приводится к нижнему;
- лишние пробелы убираются;
- сравнение идёт по нормализованной форме.

Для больших списков недопустимых лекарств:

- используйте поиск;
- фильтруйте по правилу, источнику, scope и активности;
- редактируйте записи через панель справа;
- удаляйте неактивные записи, если они больше не нужны.

## Зависимости

1. **Правило → категория**
   - `rules.category` должен совпадать с `categories.name`.
   - Категория не обязательна технически, но без неё правило хуже отображается в отчётах.

2. **Термин → правило**
   - `terms.rule_code` должен совпадать с `rules.code`.
   - Обычно используется для правил типа `term`.

3. **Правило → шаблон**
   - Для `structural`, `exact`, `synonym`, `regex` шаблон используется напрямую.
   - Для `term` шаблон может быть пустым или содержать только `sub:`.

4. **Правило → отметки**
   - После применения правил каждая отметка хранит `rule_code`, `category`, `severity`, `amount`, `rationale`.

## Сводка и очередь

**Сводка** показывает, сколько позиций отмечено каждым правилом и по каким категориям.

**Очередь** показывает позиции, которые не распознаны ни одним правилом. Там же выводятся частотные слова-кандидаты для новых терминов.

## Пакет справочников

В **Настройки** есть экспорт и импорт пакета справочников в JSON.

Пакет содержит:

- категории;
- правила;
- термины.

Это удобно для переноса настроек между базами.
