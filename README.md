# audit105

Аудит оборота по счёту 105: импорт ODS/XLSX/XML, разбор позиций, применение правил, отчёты и сравнение прогонов.

## Главное меню

Меню **Импорт**: импорт оборотов, импорт федерального справочника (ЕСКЛП/ГРЛС),
заглушки импорта и экспорта правил.

Справочники вынесены в отдельное меню:

- **Правила → Правила** — редактирование правил.
- **Правила → Категории** — редактирование категорий.
- **Правила → Термины и списки** — редактирование терминов, в том числе больших списков недопустимых лекарств.
- **Правила → Сводка и очередь** — сводка по прогону и позиции, которые не распознаны ни одним правилом.
- **Вид → Журнал событий** — прокручиваемая история: какой файл открыт, сколько строк
  обработано, что импортировано, какие ошибки возникли.

Каждая форма справочника содержит:

- фильтры и поиск;
- таблицу записей слева;
- панель редактирования справа;
- кнопки **Добавить**, **Сохранить**, **Удалить**, **Пред.**, **След.**, **Сбросить**;
- пагинацию для больших списков.

## Категории

Категория — это группа правил и цветовая метка в отчётах.

Поля:

- `name` — название категории;
- `color` — цвет в формате `#RRGGBB`;
- `description` — пояснение;
- `sort_order` — порядок отображения;
- `active` — активна ли категория.

Правила ссылаются на категорию по имени. Если категория удалена, правило остаётся, но теряет смысловую группу.

## Правила

Правило описывает, как отметить позицию.

Поля:

- `code` — уникальный код правила, например `S01`;
- `category` — название категории;
- `type` — тип правила;
- `pattern` — шаблон проверки;
- `severity` — серьёзность от 0 до 3;
- `rationale` — основание/пояснение;
- `source_doc` — источник правила;
- `active` — применять ли правило.

Порядок применения правил:

```text
structural → exact → synonym → term → regex
```

Позиция может получить несколько отметок от разных правил.

## Общий синтаксис шаблона

Для большинства типов правила шаблон может содержать ограничение по субсчётам:

```text
sub:105.31,105.32; <тело шаблона>
```

Если `sub:` отсутствует, правило применяется ко всем субсчётам.

## Типы правил

### structural

Проверяет арифметику и структуру позиции.

Возможные шаблоны:

```text
arith
qty_missing
qty_mismatch
negative
no_turnover:10000
zero_qty
```

Пример:

```text
sub:105.31,105.32; no_turnover:10000
```

Значения:

- `arith` — не сходится арифметика: начало + оборот не равно конец;
- `qty_missing` — нет строки количества;
- `qty_mismatch` — сумма и количество заполнены неравномерно;
- `negative` — отрицательный остаток на конец периода;
- `no_turnover:threshold` — нет оборота, но остаток больше порога;
- `zero_qty` — сумма есть, количество нулевое.

### exact

Ищет точные дубликаты.

Возможные шаблоны:

```text
signature
name
```

Пример:

```text
sub:105.31; name
```

Значения:

- `signature` — совпадают наименование, субсчёт и все суммы;
- `name` — совпадают наименование и субсчёт.

### synonym

Ищет позиции по списку синонимов.

Шаблон — список слов через запятую:

```text
шприц, игла, инъекция
```

Пример с субсчётами:

```text
sub:105.31; шприц, игла
```

Синонимы сравниваются с нормализованным наименованием позиции.

### term

Правило типа `term` использует справочник терминов.

Связь:

```text
rule.code = term.rule_code
```

Если для правила есть активные термины, они используются как список совпадений. Если терминов нет, используется тело шаблона правила как запасной список.

Пример:

```text
Правило: T01, type = term, pattern = sub:105.31;
Термины: иммуноглобулин, вакцины, перевязочные материалы
```

### regex

Ищет наименование позиции по регулярному выражению.

Шаблон — ECMAScript-подобное регулярное выражение:

```text
^вакцина|иммуноглобулин
```

Пример с субсчётами:

```text
sub:105.31; ^вакцина
```

## Термины и списки

Термин — это запись справочника, которая привязывается к правилу типа `term`.

Поля:

- `rule_code` — код правила;
- `term` — исходный термин;
- `term_norm` — нормализованный термин;
- `scope` — область применения, например `local` или `global`;
- `origin` — источник: `manual` или `import`;
- `list_name` — название перечня;
- `source_doc` — документ-источник;
- `as_of_date` — дата актуальности;
- `confidence` — уверенность импорта: 3 (АТХ/ОКПД2), 2 (ФТГ), 1 (маска), 0 (ручная запись);
- `active` — активен ли термин.

Нормализация:

- регистр приводится к нижнему;
- лишние пробелы убираются;
- сравнение идёт по нормализованной форме.

Для больших списков недопустимых лекарств:

- используйте поиск;
- фильтруйте по правилу, источнику, scope и активности;
- фильтруйте «Только импортированные» и смотрите колонку «Уверенность»;
- редактируйте записи через панель справа;
- удаляйте неактивные записи, если они больше не нужны.

## Зависимости

1. **Правило → категория**
   - `rules.category` должен совпадать с `categories.name`.
   - Категория не обязательна технически, но без неё правило хуже отображается в отчётах.

2. **Термин → правило**
   - `terms.rule_code` должен совпадать с `rules.code`.
   - Обычно используется для правил типа `term`.

3. **Правило → шаблон**
   - Для `structural`, `exact`, `synonym`, `regex` шаблон используется напрямую.
   - Для `term` шаблон может быть пустым или содержать только `sub:`.

4. **Правило → отметки**
   - После применения правил каждая отметка хранит `rule_code`, `category`, `severity`, `amount`, `rationale`.

## Сводка и очередь

**Сводка** показывает, сколько позиций отмечено каждым правилом и по каким категориям.

**Очередь** показывает позиции, которые не распознаны ни одним правилом. Там же выводятся частотные слова-кандидаты для новых терминов.

## Отчёт (Сводка и экспорт)

Форма **Отчёты → Сводка и экспорт** фильтрует строки по правилам, категории, субсчёту,
минимальному остатку и поиску. Фильтр действует и на экспорт (CSV и HTML), поэтому печать
и детальный разбор можно делать только по выбранным правилам.

- фон строки — цвет категории правила, красный — арифметика не сходится (как в Форме МЗ);
- чекбоксы «Правила прогона» выбирают, какие правила включать: строка попадает в выборку,
  если хотя бы одно её правило отмечено;
- CSV содержит только строки выборки (одна строка на сработавшее правило);
- HTML содержит описание фильтра, сводки по категориям/правилам/субсчётам и цветовую
  подсветку строк реестра.

Тот же фильтр по правилам (чекбоксы «Правила прогона») есть в **Форме МЗ → Таблица позиций**:
строка остаётся в таблице, если хотя бы одно её правило отмечено; «Все правила» — фильтр
не применяется.

## Пакет справочников

В меню **Импорт → Импорт и экспорт правил** есть экспорт и импорт пакета справочников в JSON
(форма «Импорт и экспорт правил»).

Пакет содержит:

- категории;
- правила;
- термины.

Это удобно для переноса настроек между базами.

## Федеральные справочники (ЕСКЛП / ГРЛС)

Цель — наполнить правила `OMS01…OMS05` («недопустимо по ОМС») не ручными примерами, а
федеральной выгрузкой ЕСКЛП из ЕГИСЗ. Фильтры строятся по международным кодам: **АТХ** для
лекарственных средств и **ОКПД2** для медицинских изделий.

### Фильтры по умолчанию

| Фильтр | Правило | Критерии |
|---|---|---|
| АРТ при ВИЧ | `OMS02` | АТХ `J05AF`, `J05AG`, `J05AR`, `J05AJ` (исключить `J05AB/AC/AD/AE` — герпес, гепатит) |
| Противотуберкулезные | `OMS03` | АТХ `J04A` |
| Вакцины | `OMS01` | АТХ `J07` |
| Тест-системы на наркотики/алкоголь | `OMS05` | ОКПД2 `21.20.23.110`, `26.60.12.119`; маски `наркотическ`, `опиат`, `каннабиноид`, `алкотест`, `этанол`, `хти` — **только для позиций без АТХ и без ФТГ** (медизделия) |

Фильтр можно включить/выключить и переназначить ему правило прямо в форме.
Совпадения импортируются в справочник терминов как `origin='import'` с указанием источника
и даты актуальности; ручные термины (`origin='manual'`) импорт никогда не перезаписывает —
совпадение уходит в раздел «Конфликты».

### Уверенность импорта (`terms.confidence`)

| Уровень | Основание |
|---|---|
| 3 | совпадение по АТХ или ОКПД2 |
| 2 | совпадение по ФТГ |
| 1 | текстовая маска (только для позиций без АТХ/ФТГ) |
| 0 | термин добавлен вручную |

При повторном импорте уверенность не понижается — берётся максимум. В редакторе терминов
есть колонка «Уверенность», фильтр «Только импортированные» и предупреждение, если дата
справочника старше 12 месяцев.

### Связка СМНН → КЛП

Файлы КЛП АТХ не содержат. `LinkEntriesByNodeCode` подтягивает АТХ и ФТГ позиции КЛП по
`код узла СМНН`, поэтому фильтр по АТХ работает и на реальных упаковках.

### Прогресс обработки и журнал событий

Чтение справочника ЕСКЛП (до ≈589 тыс. строк) занимает минуты, поэтому оно выполняется
в отдельном потоке и всегда видно:

- в статус-баре — последнее событие, прогресс-бар и подпись «идёт обработка, N с —
  это не зависание»;
- в форме справочника — «Обработано X из ~Y строк | совпадений: Z» и кнопка
  **«Отменить чтение»**;
- импорт перечней идёт по одному перечню за кадр с прогрессом «перечней N из M».

Кнопка **«журнал»** в статус-баре (или **Вид → Журнал событий**) открывает прокручиваемое
окно со всей историей событий (уровни: info/warn/error/success, время, кнопка «Очистить»).

Если в файле нет совпадений с фильтрами, повторного скана не происходит: появляется ошибка
и кнопка **«Повторить чтение файла»**.

Файловые диалоги защищены от «залипания»: `App::OpenFileDialog` закрывает диалог, открытый
другой формой, а watchdog в основном цикле закрывает диалог, у которого нет owning-формы.
Поэтому после неудачного импорта окно выбора файла снова открывается без перезапуска
приложения.

- `esklp_klp_20261014_00000…00008.xlsx` — ≈589 тыс. позиций КЛП (АТХ нет, есть код узла СМНН);

- `esklp_group_20261014.xlsx` — группы взаимозаменяемых ЛП.

## Ручной справочник ЛС (CSV)

В проекте есть накапливаемый файл `data/manual_oms_terms.csv` — ручной перечень лекарственных средств,
которые не должны закупаться за счёт ОМС (профили ВИЧ/СПИД, туберкулёз, наркология, вакцины,
тест-системы и т. п.).

- Файл обновляется по запросу к модели при анализе новых выгрузок оборота по счёту 105:
  позиции проверяются, составляется список потенциально недопустимых ЛС, и он дополняется
  в CSV.
- Файл можно редактировать вручную: это обычный CSV с разделителем `;`, колонки `term`, `profile`,
  `list_name`, `source_doc`, `as_of_date`, `scope`, `active`.
- Импорт в справочник терминов и списки: меню **Импорт → Импорт ручного перечня ЛС (CSV)**.
- Профиль отображается в одно из правил `OMS01…OMS05` (или `OMS06` для базового синонимного фильтра),
  после чего правила переприменяются к прогонам.
- По умолчанию в новой базе термины-примеры почти пусты: оставлен один пример `OMS01` («вакцин»);
  остальные накапливаются вручную, из CSV или через ЕСКЛП.
- Правило `OMS06` (синонимы `нарко, сифили, вакцин, алко, вич, туберкулез, гепатит В, …`)
  срабатывает даже без подключённых перечней; ОС-правила также расширены словами
  `системный блок, генератор, дизель-генератор`.
- Предполагается, что таких ЛС будет немного; федеральный импорт (ЕСКЛП/ГРЛС) при этом
  остаётся основным источником.

## Установка в систему (Linux)

```bash
cmake -S . -B build
cmake --build build -j4
sudo cmake --install build
```

По умолчанию используется префикс `/usr/local` (задан в `CMakeLists.txt`):

- исполняемый файл — `/usr/local/bin/audit105`;
- шрифты и ресурсы (`Roboto-Regular.ttf`, `fa-solid-900.otf`, `audit105.svg`,
  `manual_oms_terms.csv`) — `/usr/local/share/audit105`;
- значок — `/usr/local/share/icons/hicolor/scalable/apps/audit105.svg`;
- файл `.desktop` — `/usr/local/share/applications/audit105.desktop`.

Можно установить в другой префикс, например `cmake -S . -B build -DCMAKE_INSTALL_PREFIX=~/.local`.
Путь к каталогу ресурсов «запекается» в binary при конфигурации, поэтому программа
находит шрифты при запуске из любого каталога.

Порядок поиска шрифтов и ресурсов (`AssetPath`):

1. `data/` в текущем каталоге (запуск из каталога проекта или сборки);
2. `data/` рядом с исполняемым файлом;
3. файл прямо рядом с исполняемым файлом;
4. стандартный каталог установки (`/usr/local/share/audit105`).

Системные зависимости: GLFW 3.3, OpenGL, SQLite3, zlib
(Debian/Ubuntu: `sudo apt install libglfw3-dev libsqlite3-dev zlib1g-dev`).
